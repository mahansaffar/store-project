# راهنمای کامل پروژه فروشگاه

این راهنما برای کسی نوشته شده که تازه برنامه‌نویسی را شروع کرده و شاید هنوز نداند پنجره، تابع، پایگاه داده یا حتی ترمینال چیست. از تعریف‌های ساده شروع می‌کنیم و قدم‌به‌قدم به فایل‌ها و کدهای همین پروژه می‌رسیم.

لازم نیست همهٔ اصطلاح‌ها را از اول حفظ کنید. هر بخش را به ترتیب بخوانید و اگر خواستید چیزی را در برنامه تغییر دهید، از قسمت مربوط به همان موضوع کمک بگیرید.

نام فایل‌ها و دستورهایی که باید در ترمینال وارد کنید با قالب کد مشخص شده‌اند تا از متن توضیحی جدا باشند.

## ۱. این برنامه چیست؟

این پروژه یک برنامهٔ دسکتاپ فروشگاهی است که با زبان **Python** ساخته شده است. برنامه یک پنجرهٔ گرافیکی دارد و برای نگهداری اطلاعات از **SQLite** استفاده می‌کند.

در نسخهٔ فعلی، بخش‌های مربوط به ورود، ساخت حساب و فراموشی رمز عبور وجود دارند. پایگاه داده هم جدول‌هایی برای کاربران، دسته‌بندی‌ها، محصولات و سفارش‌ها آماده می‌کند. صفحه‌های کامل فروشگاه و مدیریت هنوز در رابط کاربری این نسخه ساخته نشده‌اند؛ بنابراین دیدن جدول محصولات در پایگاه داده به این معنی نیست که صفحهٔ نمایش محصولات هم آماده است.

به زبان خیلی ساده:

- Python دستورهایی را اجرا می‌کند.
- Tkinter پنجره‌ها، دکمه‌ها و کادرهای متنی را نشان می‌دهد.
- SQLite اطلاعات را داخل یک فایل روی همین رایانه نگه می‌دارد.

### چند واژهٔ ساده

| واژه | معنی ساده |
|---|---|
| برنامه | مجموعه‌ای از دستورها که رایانه اجرا می‌کند |
| رابط کاربری یا UI | چیزهایی که روی صفحه می‌بینید و با آن‌ها کار می‌کنید |
| کد | دستورهایی که برنامه‌نویس برای رایانه می‌نویسد |
| فایل | محلی برای نگهداری متن، کد یا اطلاعات |
| پوشه | محلی برای مرتب‌کردن چند فایل |
| پایگاه داده | روشی برای نگهداری مرتب اطلاعات، مثل کاربران و محصولات |
| اجرا کردن | شروع برنامه تا دستورهایش یکی‌یکی انجام شوند |

## ۲. برای شروع چه چیزهایی لازم است؟

برای اجرای این پروژه به Python و یک ویرایشگر کد مثل Visual Studio Code نیاز دارید. این برنامه برای اجزای اصلی خود از ابزارهایی استفاده می‌کند که همراه Python هستند؛ برای اجرای نسخهٔ فعلی نیازی به نصب کتابخانهٔ جانبی با `pip` نیست.

### باز کردن پوشهٔ پروژه

۱. پوشهٔ اصلی پروژه را در Visual Studio Code باز کنید؛ همان پوشه‌ای که فایل `main.py` داخل آن است.

۲. از منوی VS Code، گزینهٔ **Terminal → New Terminal** را انتخاب کنید. پایین پنجره یک ترمینال باز می‌شود.

ترمینال جایی است که می‌توانید با نوشتن یک دستور، از رایانه بخواهید کاری انجام دهد. برای مثال، با دستور اجرای Python می‌گوییم فایل شروع برنامه را اجرا کند.

برای اینکه ببینید Python در ترمینال شناخته می‌شود، این دستور را بنویسید:

```powershell
py -3 --version
```

اگر شماره‌ای مانند `Python 3.x.x` دیدید، ترمینال Python را پیدا کرده است. اگر این دستور کار نکرد، `python --version` را امتحان کنید.

### اجرای برنامه

در ترمینال VS Code یکی از این دستورها را وارد کنید:

```powershell
py -3 main.py
```

اگر دستور بالا در رایانهٔ شما شناخته نشد، این دستور را امتحان کنید:

```powershell
python main.py
```

پس از اجرا، پنجرهٔ برنامه باز می‌شود. برای بستن برنامه، پنجره را ببندید یا در ترمینال `Ctrl+C` را فشار دهید.

> نکته: ترمینال باید در پوشهٔ اصلی پروژه باشد؛ یعنی همان جایی که `main.py` قرار دارد. اگر پیام پیدا نشدن فایل دیدید، احتمالاً ترمینال در پوشهٔ دیگری باز شده است.

### آیا باید چیزی نصب کنم؟

برای همین نسخه، Python باید نصب باشد و نصب آن باید Tkinter را هم در دسترس قرار داده باشد. SQLite و ماژول `sqlite3` نیز معمولاً همراه Python هستند. اگر هنگام اجرا پیامی دربارهٔ نبودن Tkinter دیدید، ممکن است نسخه یا روش نصب Python در رایانهٔ شما این بخش را شامل نشده باشد.

## ۳. برنامه از کجا شروع می‌شود؟

وقتی دستور `py -3 main.py` را اجرا می‌کنید، Python فایل `main.py` را می‌خواند و دستورهای داخل آن را به ترتیب انجام می‌دهد. این فایل نقطهٔ شروع برنامه است؛ شبیه درِ ورودی یک ساختمان.

در `main.py` این کارها انجام می‌شوند:

۱. پایگاه داده آماده می‌شود.

۲. پنجرهٔ اصلی Tkinter ساخته می‌شود.

۳. کلاس برنامهٔ ورود و ثبت‌نام به پنجره وصل می‌شود.

۴. حلقهٔ اصلی Tkinter شروع می‌شود تا پنجره باز بماند و کلیک‌ها و تایپ‌های کاربر را دریافت کند.

به بیان ساده، حلقهٔ اصلی مثل نگهبانی است که منتظر می‌ماند کاربر کاری انجام دهد. اگر این حلقه شروع نشود، پنجره ممکن است فوراً بسته شود.

### تابع و شرط شروع فایل

در Python معمولاً بخشی از برنامه را داخل **تابع** می‌گذاریم:

```python
def main():
    print("سلام")
```

`def` یعنی «دارم یک تابع تعریف می‌کنم». نام این تابع `main` است و دستورهای تو‌رفتهٔ زیر آن، بدنهٔ تابع هستند.

این الگو در انتهای فایل Python را مطمئن می‌کند که تابع شروع را فقط وقتی اجرا کند که همین فایل را مستقیماً اجرا کرده‌ایم:

```python
if __name__ == "__main__":
    main()
```

فعلاً کافی است بدانید این بخش به Python می‌گوید: «اگر کاربر این فایل را به‌عنوان برنامهٔ اصلی اجرا کرده، از تابع `main` شروع کن.»

## ۴. چند مفهوم پایهٔ Python که در پروژه می‌بینید

### متغیر: یک اسم برای نگهداری مقدار

```python
username = "ali"
```

اینجا یک متغیر به نام `username` ساخته‌ایم و متن `ali` را در آن گذاشته‌ایم. مثل برچسب روی یک جعبه است: هر وقت به `username` مراجعه کنیم، مقدار داخل آن را می‌خوانیم.

### تابع: دستورهای نام‌گذاری‌شده

```python
def greet(name):
    return "سلام " + name
```

تابع `greet` یک ورودی به نام `name` می‌گیرد. `return` نتیجه را به جایی که تابع را صدا زده برمی‌گرداند.

در بعضی تابع‌های پروژه، کنار ورودی و خروجی نشانهٔ نوع می‌بینید؛ مثلاً `password: str` یعنی انتظار داریم `password` متن باشد و `-> str` یعنی نتیجهٔ تابع هم متن است. این‌ها راهنمای خواندن کد هستند و خودشان مقدار را تبدیل یا بررسی نمی‌کنند.

```python
message = greet("سارا")
```

پس از این خط، مقدار `message` برابر `سلام سارا` است.

### شرط: انتخاب بر اساس وضعیت

```python
if password == "1234":
    print("رمز درست است")
else:
    print("رمز اشتباه است")
```

`if` یعنی «اگر». اگر شرط درست باشد، دستورهای زیر آن اجرا می‌شوند. `else` یعنی «در غیر این صورت».

در برنامه ممکن است این شکل را هم ببینید:

```python
if view_name == "login":
    ...
elif view_name == "register":
    ...
else:
    ...
```

`elif` کوتاه‌شدهٔ «وگرنه اگر» است. برنامه نام صفحه را بررسی می‌کند و بخش مناسب را اجرا می‌کند.

### کلاس و شیء: یک الگو و نمونه‌ای از آن

کلاس را می‌توانید مثل نقشهٔ ساخت وسیله در نظر بگیرید. از روی نقشه، یک نمونهٔ واقعی می‌سازیم که به آن **شیء** می‌گوییم.

در این پروژه، کلاس برنامه مسئول نگهداری پنجره و عوض‌کردن صفحه‌هاست. وقتی از روی کلاس یک برنامه ساخته می‌شود، اطلاعات همان نمونه در `self` نگهداری می‌شود.

```python
class Example:
    def show_message(self):
        print("سلام")
```

در متدهای کلاس، `self` به همان نمونه‌ای اشاره می‌کند که متد متعلق به آن است. برای نمونه، `self.root` یعنی پنجرهٔ اصلی متعلق به این برنامه.

### فاصلهٔ ابتدای خط مهم است

در Python، فاصلهٔ ابتدای خط مشخص می‌کند یک دستور داخل کدام تابع یا شرط قرار دارد. این فاصله‌ها را **تو‌رفتگی** می‌گویند:

```python
if True:
    print("این دستور داخل شرط است")
```

اگر تو‌رفتگی اشتباه باشد، Python ممکن است خطای نحوی بدهد یا دستور در بخش نادرستی قرار بگیرد. در VS Code معمولاً بهتر است از کلید Tab و قالب‌بندی خودکار استفاده کنید.

### علامت‌ها و کلمه‌هایی که زیاد می‌بینید

| شکل | معنی |
|---|---|
| `name = "Sara"` | مقدار را در متغیر بگذار؛ `=` برای انتساب است |
| `name == "Sara"` | دو مقدار را با هم مقایسه کن؛ `==` برای پرسیدن «برابرند؟» است |
| `entry.get()` | تابع یا متدی به نام `get` را از شیء `entry` اجرا کن؛ نقطه به عضو شیء دسترسی می‌دهد |
| `user["role"]` | مقدار کلید `role` را از دیکشنری `user` بخوان |
| `True` و `False` | مقدارهای درست و نادرست؛ نتیجهٔ شرط‌ها |
| `None` | فعلاً هیچ نتیجه یا شیئی وجود ندارد |
| `len(password)` | تعداد نویسه‌های متن `password` را بده |
| `text.lower()` | حروف انگلیسی متن را کوچک کن؛ برای یکسان‌سازی پاسخ‌ها مفید است |
| `f"سلام {name}"` | متن قالب‌دار؛ مقدار متغیر `name` را داخل متن بگذار |

این دو خط را اشتباه نگیرید: `password = "1234"` رمز را در متغیر می‌گذارد؛ `password == "1234"` بررسی می‌کند مقدار آن همان متن باشد.

گاهی کد برای مدیریت خطا از این ساختار استفاده می‌کند:

```python
try:
    # کاری را امتحان کن
    ...
except Exception:
    # اگر خطا رخ داد، این بخش را اجرا کن
    ...
```

`try` یعنی تلاش کن و `except` یعنی اگر خطایی پیش آمد، آن را دریافت کن. در ثبت‌نام پروژه، این ساختار کمک می‌کند اتصال دیتابیس در صورت بروز خطا هم بسته شود و پیام خطا برگردد.

## ۵. پنجرهٔ گرافیکی با Tkinter

**Tkinter** ابزاری است که همراه Python برای ساخت پنجره‌های سادهٔ دسکتاپ می‌آید.

یک نمونهٔ خیلی کوچک:

```python
import tkinter as tk

window = tk.Tk()
label = tk.Label(window, text="سلام!")
label.pack()
window.mainloop()
```

این چند خط چه می‌کنند؟

- `import tkinter as tk` ابزار Tkinter را وارد می‌کند و برای نوشتن نامش از شکل کوتاه `tk` استفاده می‌کند.
- `tk.Tk()` یک پنجرهٔ اصلی می‌سازد.
- `tk.Label(...)` یک نوشته داخل پنجره می‌سازد.
- `pack()` به Tkinter می‌گوید آن نوشته را در پنجره جاگذاری کند.
- `mainloop()` پنجره را باز نگه می‌دارد و منتظر کار کاربر می‌ماند.

### ویجت یعنی چه؟

هر قطعهٔ قابل‌دیدن یا قابل‌استفاده در پنجره را **ویجت** می‌گویند؛ مثلاً:

- `Label`: نوشته یا عنوان
- `Entry`: کادر ورود متن
- `Button`: دکمه
- `Frame`: یک بخش یا محفظه برای گروه‌بندی ویجت‌های دیگر
- `Canvas`: سطحی برای رسم شکل یا تصویر

ویجت‌ها معمولاً یک **والد** دارند. مثلاً یک دکمه داخل یک `Frame` قرار می‌گیرد و آن `Frame` داخل پنجره است. این رابطه شبیه قرارگرفتن یک جعبه در جعبهٔ بزرگ‌تر است.

### چیدمان ویجت‌ها

Tkinter چند روش برای چیدن ویجت‌ها دارد. این پروژه بیشتر از `pack()` استفاده می‌کند.

```python
button.pack(fill="x", padx=20, pady=10)
```

- `fill="x"`: ویجت را در راستای افقی بکش.
- `padx=20`: از چپ و راست کمی فاصله بده.
- `pady=10`: از بالا و پایین کمی فاصله بده.
- `expand=True`: اگر فضای خالی بود، اجازه بده ویجت از آن استفاده کند.

این گزینه‌ها فقط نمونه‌هایی برای فهم مفهوم هستند. برای تغییر ظاهر اصلی پروژه، قبل از هر تغییری مشخص کنید کدام گزینه چه اثری دارد.

### دکمه چگونه کاری انجام می‌دهد؟

دکمه معمولاً یک تابع را برای زمان کلیک نگه می‌دارد:

```python
button = tk.Button(window, text="ورود", command=login)
```

اینجا `login` بدون پرانتز نوشته شده، چون می‌خواهیم خود تابع را به دکمه معرفی کنیم تا بعداً، هنگام کلیک، اجرا شود. اگر بنویسیم `command=login()`، تابع همان لحظه اجرا می‌شود؛ این اشتباه رایج است.

اگر تابع به اطلاعات بیشتری نیاز داشته باشد، در پروژه از `lambda` استفاده می‌شود:

```python
command=lambda: submit(app)
```

`lambda` راه کوتاهی برای ساخت یک تابع کوچک است. در این مثال، هنگام کلیک، تابع `submit` با برنامهٔ فعلی صدا زده می‌شود.

### رویدادهای صفحه‌کلید

گاهی برنامه باید به یک اتفاق، مثل فشردن کلید Enter، واکنش نشان دهد. به چنین اتفاقی **رویداد** می‌گوییم. متد `bind` می‌تواند یک رویداد را به تابع وصل کند. مثلاً در صفحهٔ ورود، فشردن Enter می‌تواند همان کار دکمهٔ ورود را انجام دهد.

## ۶. نقشهٔ فایل‌های پروژه

هر فایل مسئول یک بخش است. این تقسیم‌بندی کمک می‌کند وقتی دنبال یک قابلیت می‌گردید، بدانید از کجا شروع کنید.

| فایل یا پوشه | کار آن |
|---|---|
| `main.py` | نقطهٔ شروع؛ آماده‌کردن پایگاه داده و بازکردن پنجره |
| `auth_window.py` | ساخت پنجرهٔ اصلی بخش حساب کاربری و جابه‌جایی بین صفحه‌ها |
| `screens/` | پوشهٔ فایل‌های مربوط به صفحه‌های برنامه |
| `screens/login.py` | ساخت صفحهٔ ورود و بررسی اطلاعاتی که کاربر وارد می‌کند |
| `screens/register.py` | ساخت صفحهٔ ساخت حساب و ثبت اطلاعات کاربر |
| `screens/forgot_password.py` | ساخت صفحهٔ بازیابی رمز عبور |
| `ui_components.py` | اجزای گرافیکی مشترکی که چند صفحه از آن‌ها استفاده می‌کنند |
| `ui_assets.py` | ابزارهای رسم پس‌زمینهٔ تدریجی با Canvas |
| `database.py` | اتصال به SQLite، ساخت جدول‌ها و خواندن یا تغییر اطلاعات |
| `store.db` | فایل دادهٔ SQLite که برنامه در کنار فایل‌های کد نگه می‌دارد و هنگام نیاز می‌سازد |

خط‌هایی مانند `from database import authenticate_user` یعنی تابع `authenticate_user` را از فایل `database.py` وارد کن. در همین شکل، `from screens import ...` صفحه‌ها را از پوشهٔ `screens` می‌آورد. فایل `screens/__init__.py` وجود دارد تا پوشه به شکل یک بستهٔ قابل‌واردکردن استفاده شود.

### چرا هر چیز را در فایل جدا گذاشته‌ایم؟

اگر تمام کد برنامه در یک فایل بسیار بزرگ باشد، پیدا کردن یک خطا یا تغییر کوچک دشوار می‌شود. جداکردن مسئولیت‌ها کمک می‌کند:

- کد ساخت پنجره را از کد دیتابیس تشخیص دهیم.
- اجزای مشترک رابط کاربری را یک بار بنویسیم و در چند صفحه استفاده کنیم.
- بعداً یک صفحهٔ جدید را بدون به‌هم‌ریختن همهٔ بخش‌ها اضافه کنیم.

این جداسازی به معنی پیچیده‌بودن کار نیست؛ هر فایل را می‌توان مثل یک فصل با موضوع مشخص در نظر گرفت.

## ۷. مسیر کاربر در صفحهٔ ورود

برای اینکه ارتباط فایل‌ها روشن شود، مسیر ورود را قدم‌به‌قدم دنبال کنیم:

۱. کاربر برنامه را اجرا می‌کند و `main.py` پنجره را می‌سازد.

۲. برنامه کلاس اصلی را از `auth_window.py` می‌سازد.

۳. برنامه صفحهٔ ورود را نمایش می‌دهد. متد `show_view` نام صفحه را می‌گیرد و با شرط‌های `if` و `elif` تصمیم می‌گیرد کدام فایل صفحه را بسازد.

۴. تابع `build(app)` در `screens/login.py` اجزای صفحه را می‌سازد.

۵. برای عنوان، کادر ورودی، دکمه و پیام از توابع مشترک `ui_components.py` کمک گرفته می‌شود.

۶. کاربر نام کاربری و رمز را وارد می‌کند و دکمه را می‌زند.

۷. تابع `submit(app)` مقدار کادرها را می‌خواند و تابع `authenticate_user` را از `database.py` صدا می‌زند.

۸. تابع دیتابیس اطلاعات را در SQLite جست‌وجو می‌کند و نتیجه را برمی‌گرداند.

۹. صفحه براساس نتیجه، پیام مناسب نشان می‌دهد.

در این نسخه، ورود موفق کاربر را به داشبورد فروشگاه یا پنل مدیریت نمی‌برد. برنامه پس از یک مکث کوتاه پنجرهٔ پیام را باز می‌کند و نام و نقش حساب را نشان می‌دهد. صفحه‌ها و مسیرهای بعد از ورود می‌توانند مرحلهٔ بعدی توسعه باشند.

### نمونهٔ واقعی: هر خط صفحهٔ ورود چه می‌کند؟

در `screens/login.py` این خط را پیدا می‌کنید:

```python
button(app, body, "ورود به حساب  ←", lambda: submit(app))
```

آن را تکه‌تکه بخوانیم:

- `button(...)` تابع کمکی پروژه است که در `ui_components.py` قرار دارد و یک دکمه می‌سازد.
- `app` برنامهٔ اصلی را به تابع می‌دهد تا تابع به رنگ‌ها و پنجره دسترسی داشته باشد.
- `body` قاب سفیدی است که دکمه باید داخل آن قرار بگیرد.
- متن داخل کوتیشن‌ها نوشته‌ای است که روی دکمه دیده می‌شود.
- `lambda: submit(app)` می‌گوید: «وقتی دکمه را کلیک کردند، تابع `submit` را با همین `app` اجرا کن.»

چرا `submit(app)` را مستقیم به `command` نمی‌دهیم؟ چون آن‌وقت تابع همان لحظه‌ای که صفحه ساخته می‌شود اجرا خواهد شد. `lambda` اجرای آن را تا زمان کلیک عقب می‌اندازد.

حالا بدنهٔ تابع `submit` را به ترتیب دنبال کنیم:

```python
username = value(app.login_user_entry).strip()
password = value(app.login_pass_entry)
```

`value(...)` متن واقعی کادر را می‌خواند. اگر کادر هنوز متن راهنمای خاکستری داشته باشد، به‌جای آن متن خالی می‌دهد. `strip()` فاصله‌های اضافی ابتدا و انتهای نام کاربری را حذف می‌کند.

```python
if not username or not password:
    show_status(app, "نام کاربری و رمز عبور را وارد کن.")
    return
```

`not username` یعنی نام کاربری خالی است؛ `or` یعنی «یا». پس اگر یکی از دو کادر خالی باشد، پیام نمایش داده می‌شود. `return` تابع را همان‌جا تمام می‌کند تا جست‌وجوی دیتابیس بی‌دلیل انجام نشود.

```python
user = authenticate_user(username, password)
if not user:
    show_status(app, "نام کاربری یا رمز عبور درست نیست.")
    return
```

اینجا صفحه از `database.py` می‌خواهد حساب را بررسی کند. اگر حساب پیدا نشود یا رمز نادرست باشد، تابع دیتابیس `None` برمی‌گرداند و `if not user` پیام خطا را نشان می‌دهد.

در صورت درست‌بودن اطلاعات، کد این کارها را انجام می‌دهد:

```python
app.current_user = user
show_status(app, "ورود موفق بود؛ در حال آماده‌سازی حساب…", error=False)
app.root.after(450, lambda: app.on_login_success(user))
```

- حساب واردشده موقتاً در `app.current_user` نگهداری می‌شود.
- پیام موفقیت با `error=False` نمایش داده می‌شود تا از رنگ موفقیت استفاده شود.
- `after(450, ...)` اجرای تابع را حدود ۴۵۰ میلی‌ثانیه عقب می‌اندازد؛ این فرصت می‌دهد پیام وضعیت دیده شود.
- `on_login_success` در `auth_window.py` پنجرهٔ پیام را باز می‌کند و نقش حساب را نشان می‌دهد.

### حالا برویم داخل تابع دیتابیس

`authenticate_user` در `database.py` نام کاربری را در جدول `users` جست‌وجو می‌کند:

```python
cursor.execute("SELECT * FROM users WHERE username = ?", (username.strip(),))
user = cursor.fetchone()
```

`SELECT *` یعنی همهٔ ستون‌های ردیف را بخوان. بخش `WHERE` نتیجه را به نام کاربری خواسته‌شده محدود می‌کند. علامت `?` جای مقدار است و تاپل `(username.strip(),)` مقدار را جداگانه به SQLite می‌دهد.

سپس تابع رمز واردشده را با هش ذخیره‌شده مقایسه می‌کند. اگر هر دو درست باشند، ردیف را به `dict` تبدیل می‌کند و برمی‌گرداند؛ در غیر این صورت `None` می‌دهد. `dict` ساختاری شبیه دفترچهٔ کلید و مقدار است، پس برنامه می‌تواند چیزهایی مثل `user["full_name"]` یا `user["role"]` را بخواند.

### فشردن Enter هم همان کار را می‌کند

در صفحهٔ ورود این خط وجود دارد:

```python
app.login_pass_entry.bind("<Return>", lambda _event: submit(app))
```

`bind` یک رویداد را به تابع وصل می‌کند. `<Return>` یعنی کلید Enter. Tkinter هنگام رویداد، اطلاعاتی دربارهٔ رویداد به تابع می‌دهد؛ پارامتر `_event` آن را می‌گیرد، اما اینجا لازم نیست از آن استفاده کنیم. به همین دلیل نامش با زیرخط شروع شده تا نشان دهد عمداً استفاده نمی‌شود.

### «مقدار ورودی» و متن راهنما

کادر ورودی گاهی متن کم‌رنگی برای راهنمایی دارد؛ مثلاً «نام کاربری». این متن ممکن است فقط راهنما باشد و نباید به‌عنوان نامی که کاربر واقعاً نوشته به دیتابیس فرستاده شود. تابع مشترک `value(...)` مقدار کادر را می‌خواند و فاصله‌های اضافی ابتدا و انتهای متن را حذف می‌کند.

متد `strip()` برای حذف فاصله‌های ابتدا و انتهاست. مثلاً:

```python
"  ali  ".strip()
```

نتیجه برابر `ali` می‌شود.

## ۸. صفحه‌های ساخت حساب و فراموشی رمز

### ساخت حساب

صفحهٔ ثبت‌نام از فایل `screens/register.py` ساخته می‌شود. این صفحه اطلاعات موردنیاز را از کادرها می‌گیرد و برای ذخیره‌کردن آن‌ها تابع `register_user` را در `database.py` فراخوانی می‌کند.

تابع ثبت‌نام باید بررسی کند که اطلاعات لازم خالی نباشند و نام کاربری تکراری نباشد. پس از آن، اطلاعات را با یک دستور SQL در جدول کاربران ثبت می‌کند.

### فراموشی رمز

صفحهٔ فراموشی رمز از `screens/forgot_password.py` می‌آید. در این پروژه، کاربر با نام کاربری و پاسخ پرسش امنیتی شناخته می‌شود. تابع‌های `get_user_security_question` و `reset_user_password` در `database.py` به ترتیب برای پیدا کردن پرسش کاربر و تغییر رمز استفاده می‌شوند.

اگر صفحه‌ای اطلاعات را از کاربر می‌گیرد، اما ذخیره یا بررسی واقعی اطلاعات را جای دیگری انجام می‌دهد، یعنی مسئولیت رابط کاربری و دیتابیس از هم جدا شده‌اند. صفحه می‌پرسد؛ لایهٔ دیتابیس اطلاعات را جست‌وجو یا ذخیره می‌کند.

## ۹. SQLite و پایگاه داده، از صفر

### پایگاه داده شبیه دفتر مرتب است

تصور کنید دفتر جدولی دارید که هر سطرش اطلاعات یک کاربر است:

| id | username | password |
|---:|---|---|
| 1 | sara | ... |
| 2 | ali | ... |

در SQLite:

- دفتر کامل را **پایگاه داده** می‌گوییم.
- هر جدول موضوع مشخصی دارد؛ مثلاً جدول کاربران.
- هر سطر یک رکورد است؛ مثلاً اطلاعات یک کاربر.
- هر ستون یک نوع اطلاعات است؛ مثلاً نام کاربری.

SQLite پایگاه داده را در یک فایل نگه می‌دارد. این پروژه فایل `store.db` را کنار کدها قرار می‌دهد. اگر فایل هنوز وجود نداشته باشد، اتصال SQLite می‌تواند آن را ایجاد کند.

### اتصال، نشانگر و دستور SQL

برای کار با SQLite معمولاً این سه مرحله را می‌بینید:

۱. اتصال به فایل پایگاه داده.

۲. ساخت یک cursor برای فرستادن دستورها.

۳. اجرای دستور SQL و خواندن نتیجه یا ذخیرهٔ تغییر.

یک مثال ساده:

```python
import sqlite3

connection = sqlite3.connect("store.db")
cursor = connection.cursor()
cursor.execute("SELECT username FROM users")
rows = cursor.fetchall()
connection.close()
```

- `connect(...)`: به فایل پایگاه داده وصل می‌شود.
- `cursor()`: ابزاری می‌سازد که از آن برای اجرای دستورها استفاده می‌کنیم.
- `execute(...)`: یک دستور SQL را اجرا می‌کند.
- `fetchall()`: همهٔ ردیف‌های نتیجه را برمی‌گرداند.
- `close()`: اتصال را می‌بندد.

در این مثال، `SELECT` می‌گوید اطلاعات را بخوان. `FROM users` می‌گوید آن اطلاعات را از جدول `users` بخوان.

### چند دستور پرکاربرد SQL

```sql
SELECT username FROM users;
```

خواندن نام کاربری‌ها.

```sql
INSERT INTO users (username) VALUES (?);
```

افزودن یک مقدار به جدول.

```sql
UPDATE users SET password = ? WHERE username = ?;
```

تغییر رمز برای کاربری که نامش مشخص است.

```sql
DELETE FROM users WHERE username = ?;
```

حذف ردیف یک کاربر مشخص.

این دستورها فقط برای آشنایی هستند. هنگام کار واقعی با این پروژه، منطق کامل اتصال و پرس‌وجو در `database.py` قرار دارد.

### چرا علامت سؤال `?` می‌گذاریم؟

در کد پروژه، مقدارهایی که کاربر نوشته مستقیماً به متن SQL چسبانده نمی‌شوند. به‌جای آن از علامت `?` و پارامتر استفاده می‌شود:

```python
cursor.execute(
    "SELECT id FROM users WHERE username = ?",
    (username,),
)
```

علامت سؤال جای مقدار را مشخص می‌کند. مقدار جداگانه به SQLite داده می‌شود. این روش امن‌تر است و از خراب‌شدن پرس‌وجو با متن‌های خاص جلوگیری می‌کند.

در `(username,)` ویرگول مهم است: در Python این شکل یعنی یک تاپل تک‌عضوی. پرانتز به‌تنهایی کافی نیست.

### ذخیرهٔ تغییر با `commit`

برای خواندن اطلاعات، معمولاً `commit()` لازم نیست. اما پس از افزودن، تغییر یا حذف داده، باید تغییرها ثبت شوند:

```python
connection.commit()
```

اگر `commit()` فراموش شود، ممکن است تغییر مورد انتظار واقعاً در فایل پایگاه داده ذخیره نشود.

### `fetchone` و `fetchall`

- `fetchone()` یک ردیف از نتیجه را می‌گیرد؛ برای جست‌وجوی یک کاربر مناسب است.
- `fetchall()` همهٔ ردیف‌های نتیجه را می‌گیرد؛ برای نمایش فهرستی از چند مورد به‌کار می‌رود.

### جدول‌های پروژه

تابع `init_db()` در `database.py` جدول‌های اولیه را آماده می‌کند:

- `users`: اطلاعات حساب کاربران
- `categories`: دسته‌بندی‌ها
- `products`: محصولات
- `orders`: سفارش‌ها
- `order_items`: محصول‌ها و تعدادشان در هر سفارش

جدول‌ها می‌توانند با کلیدها به یکدیگر ارتباط داشته باشند. برای مثال، سفارش به کاربری تعلق دارد و هر ردیف سفارش می‌تواند به محصولی اشاره کند.

در ساخت جدول‌ها معمولاً این واژه‌ها را می‌بینید:

- `PRIMARY KEY`: شناسهٔ یکتای هر ردیف.
- `FOREIGN KEY`: ارتباط یک جدول با ردیف جدول دیگر.
- `NOT NULL`: این مقدار نباید خالی باشد.
- `UNIQUE`: این مقدار نباید تکراری باشد؛ مثلاً نام کاربری.
- `IF NOT EXISTS`: جدول را فقط در صورتی بساز که از قبل وجود ندارد.

### نمونهٔ واقعی: ثبت‌نام چگونه کاربر را ذخیره می‌کند؟

در صفحهٔ ثبت‌نام (`screens/register.py`) اطلاعات فرم خوانده و به تابع دیتابیس فرستاده می‌شوند. این خط چند مقدار را هم‌زمان از یک تابع دریافت می‌کند:

```python
success, text = register_user(username, password, full_name, question, answer)
```

تابع `register_user` دو مقدار برمی‌گرداند: درست یا نادرست بودن کار (`success`) و متنی برای نمایش به کاربر (`text`). اینجا Python نتیجهٔ اول را در `success` و دومی را در `text` می‌گذارد. به این شیوه **بازکردن چند مقدار در چند متغیر** می‌گویند.

در تابع `register_user`، ترتیب کار این است:

۱. با `strip()` فاصلهٔ اضافی اول و آخر نام کاربری پاک می‌شود.

۲. اگر نام کاربری، رمز یا نام کامل خالی باشد، تابع `False` و پیام مناسب برمی‌گرداند.

۳. اگر رمز کمتر از ۴ نویسه باشد، ثبت‌نام متوقف می‌شود.

۴. برنامه به دیتابیس وصل می‌شود و بررسی می‌کند این نام کاربری قبلاً ثبت نشده باشد. ستون `username` در جدول هم `UNIQUE` است؛ بنابراین خود SQLite نیز تکراری‌بودن آن را منع می‌کند.

۵. رمز از `hash_password` عبور می‌کند و مقدار هش‌شده برای ذخیره آماده می‌شود.

۶. دستور `INSERT` یک کاربر با نقش `user` می‌سازد. مقادیر ورودی با `?` جدا از متن SQL فرستاده می‌شوند.

۷. `commit()` تغییر را ذخیره می‌کند، `close()` اتصال را می‌بندد و تابع پیام موفقیت را برمی‌گرداند.

۸. صفحهٔ ثبت‌نام پیام را نمایش می‌دهد و اگر موفق بوده، پس از کمی مکث کاربر را به صفحهٔ ورود برمی‌گرداند.

پس از موفقیت، مقدار `success` برابر `True` می‌شود؛ هنگام خطا `False` است. `if success:` یعنی «اگر ثبت‌نام موفق بود، دستورهای داخل شرط را اجرا کن».

### نمونهٔ واقعی: بازیابی رمز چگونه کار می‌کند؟

در صفحهٔ بازیابی، دو رویداد مهم داریم:

- وقتی کاربر از کادر نام کاربری بیرون می‌رود (`<FocusOut>`)، تابع `on_username_blur` اجرا می‌شود. تابع پرسش امنیتی را از دیتابیس می‌گیرد و روی صفحه نشان می‌دهد.
- وقتی کاربر رمز تازه را تایپ می‌کند (`<KeyRelease>`)، تابع `update_password_strength` طول رمز را می‌سنجد و نوار راهنما را به‌روز می‌کند.

هنگام فشردن دکمهٔ ذخیره، تابع `submit` مقدار نام کاربری، پاسخ امنیتی و رمز تازه را می‌خواند. سپس `reset_user_password` در `database.py` پرسش امنیتی را بررسی می‌کند. اگر پاسخ درست و رمز حداقل ۴ نویسه باشد، رمز تازه هش می‌شود و دستور `UPDATE` مقدار `password_hash` همان کاربر را عوض می‌کند. پس از `commit()`، اتصال بسته می‌شود و صفحه پیام نتیجه را نشان می‌دهد.

### تمرین SQLite با فایل جداگانه

این تمرین را در فایلی جدا به نام `sqlite_practice.py` انجام دهید. در VS Code، در فهرست فایل‌ها روی پوشهٔ اصلی پروژه کلیک راست کنید، **New File** را بزنید، نام فایل را وارد کنید، کد زیر را در فایل خالی بچسبانید و با `Ctrl+S` ذخیره کنید. سپس آن را از پوشهٔ اصلی پروژه با دستور `py -3 sqlite_practice.py` اجرا کنید.

تمرین از فایل `practice.db` استفاده می‌کند تا داده‌های واقعی برنامه در `store.db` دست‌نخورده بمانند. در دستور `CREATE TABLE` سه‌کوتیشن `"""` اجازه می‌دهد دستور SQL را در چند خط بنویسیم؛ Python همهٔ این خطوط را به‌عنوان یک متن به SQLite می‌فرستد. تنظیم `row_factory` باعث می‌شود ردیف نتیجه با نام ستون خوانده شود، مثل `note["title"]`.

```python
import sqlite3

connection = sqlite3.connect("practice.db")
connection.row_factory = sqlite3.Row
cursor = connection.cursor()

cursor.execute("""
CREATE TABLE IF NOT EXISTS notes (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL
)
""")

cursor.execute(
    "INSERT INTO notes (title) VALUES (?)",
    ("یادگیری SQLite",),
)
note_id = cursor.lastrowid

cursor.execute(
    "UPDATE notes SET title = ? WHERE id = ?",
    ("SQLite را تمرین می‌کنم", note_id),
)
connection.commit()

cursor.execute("SELECT id, title FROM notes WHERE id = ?", (note_id,))
note = cursor.fetchone()
print(f"{note['id']} - {note['title']}")

# برای تمرین حذف، دو خط زیر را از حالت توضیح خارج کنید:
# cursor.execute("DELETE FROM notes WHERE id = ?", (note_id,))
# connection.commit()

connection.close()
```

این برنامه جدول `notes` را می‌سازد، یک یادداشت اضافه می‌کند، عنوان همان یادداشت را تغییر می‌دهد، آن را می‌خواند و چاپ می‌کند. `cursor.lastrowid` شناسه‌ای را می‌دهد که SQLite برای ردیف تازه ساخته است. هر بار اجرای این فایل یک یادداشت تازه اضافه می‌کند؛ اما فقط همان یادداشت تازه را ویرایش و نمایش می‌دهد.

در اولین اجرا، خروجی نمونه می‌تواند این باشد:

```text
1 - SQLite را تمرین می‌کنم
```

اگر فایل را دوباره اجرا کنید، شمارهٔ ردیف ممکن است بیشتر شود، چون هر اجرا یک یادداشت تازه می‌سازد.

- `CREATE TABLE`: ساخت جدول.
- `INSERT`: افزودن ردیف.
- `UPDATE`: تغییر ردیف موجود.
- `SELECT`: خواندن ردیف.
- `DELETE`: حذف ردیف.
- `connection.commit()`: ثبت تغییرهای انجام‌شده.
- `connection.close()`: پایان اتصال.

سه دستور تغییر‌دهنده (`INSERT`، `UPDATE`، `DELETE`) را با علامت سؤال و پارامتر نوشته‌ایم. این روش را در کد پروژه هم می‌بینید.

## ۱۰. فایل داده را با فایل کد اشتباه نگیریم

فایل‌های `.py` دستورهای برنامه هستند. فایل `store.db` اطلاعات ذخیره‌شده است. این دو یک کار انجام نمی‌دهند:

- تغییر `database.py` یعنی تغییر دستورهایی که با داده کار می‌کنند.
- تغییر `store.db` یعنی تغییر خود اطلاعات ذخیره‌شده.

اگر یک حساب ثبت کردید، احتمالاً اطلاعاتش در `store.db` باقی می‌ماند، حتی اگر برنامه را ببندید و دوباره باز کنید. این همان فایدهٔ پایگاه داده است.

### نکتهٔ مهم دربارهٔ تغییر جدول‌ها

اگر در کد، تعریف یک جدول موجود را تغییر دهید، `CREATE TABLE IF NOT EXISTS` جدول قدیمی را به‌طور خودکار از نو نمی‌سازد و ستون تازه را به آن اضافه نمی‌کند. این دستور فقط وقتی جدول وجود ندارد آن را ایجاد می‌کند.

پس از تغییر ساختار جدول، ممکن است پایگاه دادهٔ قدیمی با کد جدید هماهنگ نباشد. برای پروژهٔ تمرینی، قبل از هر کار از فایل داده کپی پشتیبان بگیرید. حذف فایل پایگاه داده می‌تواند اطلاعات ذخیره‌شده را از بین ببرد؛ بدون اینکه بدانید داخل آن چیست، آن را حذف نکنید.

## ۱۱. رنگ‌ها و اجزای مشترک را از کجا تغییر بدهیم؟

### رنگ‌های اصلی

در کلاس `LuxuryAuthApp` در فایل `auth_window.py`، دیکشنری `COLORS` رنگ‌های مشترک برنامه را نگه می‌دارد. **دیکشنری** مجموعه‌ای از جفت‌های «کلید و مقدار» است. در کد واقعی، مثلاً کلید `paper` رنگ سطح روشن فرم و کلید `plum` رنگ اصلی بنفش را نگه می‌دارد:

```python
class LuxuryAuthApp:
    COLORS = {
        "paper": "#ffffff",
        "plum": "#56334f",
    }
```

در این مثال کوتاه‌شده، `paper` و `plum` نام رنگ‌ها هستند و مقدار روبه‌رویشان کد رنگ است. در صفحه‌ها رنگ را با عبارتی مثل `app.COLORS["paper"]` می‌خوانیم. صفحه‌ها از همین رنگ‌های مشترک استفاده می‌کنند تا رنگ‌های تکراری در چند فایل پراکنده نشوند.

### اجزای مشترک

در `ui_components.py` توابع مشترکی برای ساخت بدنهٔ فرم، عنوان، فیلد، دکمه، لینک و پیام وضعیت وجود دارد. اگر چند صفحه از یک نوع دکمه استفاده می‌کنند، ساخت آن در یک تابع مشترک باعث می‌شود رفتار و ظاهرشان هماهنگ بماند.

### پس‌زمینهٔ تدریجی

`ui_assets.py` ابزارهایی برای تبدیل کد رنگ و رسم گرادیان عمودی روی Canvas دارد. گرادیان یعنی رنگ در طول سطح به‌آرامی تغییر کند. اگر با این مفهوم آشنا نیستید، لازم نیست برای خواندن منطق ورود یا دیتابیس ابتدا این فایل را یاد بگیرید.

## ۱۲. برای هر تغییر از کجا شروع کنم؟

| کاری که می‌خواهید انجام دهید | فایل مناسب برای شروع |

| عوض‌کردن عنوان یا نوشتهٔ یک صفحه | فایل همان صفحه داخل `screens/` |

## ۱۳. اگر بعداً صفحهٔ تازه‌ای اضافه کنیم

صفحه‌های این پروژه در پوشهٔ `screens/` قرار می‌گیرند. هر صفحه یک تابع `build(app)` دارد که ویجت‌های آن را می‌سازد. برای اضافه‌کردن یک صفحه، به‌طور کلی این مراحل را دنبال می‌کنیم:

۱. یک فایل تازه داخل `screens/` می‌سازیم؛ مثلاً `help_page.py`.

۲. داخل آن تابعی با شکل `build(app)` می‌نویسیم و ویجت‌های صفحه را در آن می‌سازیم.

۳. ماژول صفحه را در `auth_window.py` وارد می‌کنیم.

۴. در متد `show_view` یک شرط `elif` برای نام صفحه اضافه می‌کنیم و تابع `build(self)` را صدا می‌زنیم.

۵. از جایی در برنامه، `show_view("help")` را فراخوانی می‌کنیم تا صفحه نمایش داده شود.

این راهنمایی دربارهٔ ساختار فعلی پروژه است؛ قبل از افزودن صفحه، نام‌گذاری و روش ساخت صفحه‌های موجود را نگاه کنید تا شیوهٔ همان پروژه را دنبال کنید.

## ۱۵. چند خطای معمول و راه‌حل اولیه

### پیام می‌گوید `main.py` پیدا نشد

ترمینال احتمالاً در پوشهٔ اصلی پروژه نیست. در VS Code مطمئن شوید پوشه‌ای را باز کرده‌اید که فایل `main.py` مستقیماً در آن دیده می‌شود و ترمینال را از همان پنجره باز کنید.

### دستور `py` یا `python` شناخته نشد

Python ممکن است نصب نباشد یا مسیر نصب آن برای ترمینال شناخته نشده باشد. اول دستور جایگزین بخش اجرای برنامه را امتحان کنید؛ اگر هیچ‌کدام کار نکرد، وضعیت نصب Python را بررسی کنید.

### پنجره ظاهر نمی‌شود یا برنامه سریع تمام می‌شود

به متن خطا در ترمینال نگاه کنید. معمولاً Python نام فایل و شمارهٔ خط را نشان می‌دهد. شمارهٔ خط را در فایل ذکرشده باز کنید و چند خط اطراف آن را بخوانید.

### خطای مربوط به جدول یا ستون پایگاه داده می‌بینم

ممکن است فایل `store.db` با ساختار فعلی کد هماهنگ نباشد؛ مثلاً کد ستونی می‌خواهد که در پایگاه دادهٔ قدیمی وجود ندارد. پیش از تغییر یا جایگزینی فایل داده، از آن نسخهٔ پشتیبان بگیرید و پیام کامل خطا را بخوانید.

### هنگام ویرایش، `IndentationError` می‌بینم

احتمالاً فاصله‌های ابتدای خط درست نیستند. مطمئن شوید دستورهای داخل تابع یا شرط یک اندازه تو‌رفته‌اند و از قابلیت قالب‌بندی VS Code استفاده کنید.

## ۱۶. مسیر تمرین برای تازه‌کارها

برای یادگیری، از تغییرهای کوچک و کم‌خطر شروع کنید. هر تمرین را اول خودتان حل کنید؛ پاسخ و دلیلش بلافاصله بعد از تمرین آمده تا بتوانید بررسی کنید.

### تمرین ۱: فهمیدن `strip()`

**سؤال:** اگر کاربر نام کاربری را به شکل `"  sara  "` وارد کند، این عبارت چه چیزی برمی‌گرداند؟

```python
"  sara  ".strip()
```

**پاسخ:** `"sara"`. فاصله‌های اول و آخر حذف می‌شوند؛ فاصله‌های وسط متن حذف نمی‌شوند.

### تمرین ۲: دنبال‌کردن ورود خالی

**سؤال:** اگر هر دو کادر ورود خالی باشند، آیا تابع دیتابیس فراخوانی می‌شود؟

**پاسخ:** خیر. `submit` ابتدا `username` و `password` را می‌خواند. شرط `if not username or not password` درست می‌شود، پیام نمایش داده می‌شود و `return` بقیهٔ تابع را متوقف می‌کند.

### تمرین ۳: دنبال‌کردن رمز اشتباه

**سؤال:** اگر نام کاربری وجود داشته باشد ولی رمز اشتباه باشد، چه مسیری طی می‌شود؟

**پاسخ:** `authenticate_user` ردیف کاربر را پیدا می‌کند، اما هش رمز ورودی با `password_hash` ذخیره‌شده برابر نیست؛ پس `None` برمی‌گرداند. صفحه پیام «نام کاربری یا رمز عبور درست نیست» را نشان می‌دهد.

### تمرین ۴: پیدا کردن جای ثبت‌نام در SQL

**سؤال:** در کدام دستور کاربر جدید به پایگاه داده اضافه می‌شود؟ کلمهٔ `INSERT` چه معنی‌ای دارد؟

```sql
INSERT INTO users (username, password_hash, full_name, role, security_question, security_answer)
VALUES (?, ?, ?, 'user', ?, ?)
```

**پاسخ:** این دستور در تابع `register_user` داخل `database.py` است. `INSERT INTO` یعنی «یک ردیف تازه داخل جدول بگذار». علامت‌های `?` با مقادیر تاپل پس از دستور پر می‌شوند. نقش کاربران معمولی در این دستور برابر `user` قرار می‌گیرد.

### تمرین ۵: پیش‌بینی رفتار رمز کوتاه

**سؤال:** هنگام ثبت‌نام، اگر رمز فقط سه نویسه باشد، آیا کاربر به جدول اضافه می‌شود؟

**پاسخ:** خیر. `register_user` طول رمز را با `len(password)` می‌سنجد. اگر کمتر از ۴ باشد، پیش از اتصال و نوشتن در پایگاه داده، `False` و پیام خطا برمی‌گرداند.

### تمرین ۶: شناخت حساب نمونه

**سؤال:** حساب مدیریتی نمونه با چه نام و رمزی ساخته می‌شود؟

**پاسخ:** نام کاربری `admin` و رمز `admin123` است. اگر بخواهید پرسش امنیتی این حساب را هم در صفحهٔ بازیابی پاسخ دهید، پرسش «نام سیستم فروشگاهی شما چیست؟» و پاسخ ذخیره‌شده «دیجی استایل» است. این اطلاعات فقط نمونهٔ آموزشی‌اند.

### تمرین ۷: خواندن یک دستور دیتابیس

**سؤال:** این دستور چه چیزی را از کجا می‌خواند؟

```sql
SELECT security_question FROM users WHERE username = ?
```

**پاسخ:** ستون `security_question` را از جدول `users` می‌خواند، آن هم فقط برای ردیفی که نام کاربری‌اش با مقدار جایگزین‌شده به‌جای `?` برابر است.

### تمرین ۸: بررسی مستقل از ظاهر

**سؤال:** اگر ظاهر دکمه را تغییر ندهیم، کدام قسمت مشخص می‌کند کلیک روی دکمهٔ ورود چه کاری انجام دهد؟

**پاسخ:** در `screens/login.py`، آرگومان `lambda: submit(app)` به تابع `button` داده شده است. تابع `button` در `ui_components.py` همین callback را به گزینهٔ `command` ویجت دکمه می‌دهد. خود `submit` رفتار ورود را اجرا می‌کند.

### تمرین ۹: افزودن یک یادداشت در تمرین SQLite

**کار:** در فایل تمرینی `sqlite_practice.py` یک دستور `INSERT` دیگر اضافه کن تا دو یادداشت در جدول تمرین ثبت شوند.

**راهنمایی و پاسخ:** دستور دوم را بلافاصله بعد از دستور `INSERT` اول و پیش از `note_id = cursor.lastrowid` بگذار:

```python
cursor.execute(
    "INSERT INTO notes (title) VALUES (?)",
    ("یادداشت دوم من",),
)
```

چون `note_id` بعد از این دستور خوانده می‌شود، شناسهٔ یادداشت دوم در آن قرار می‌گیرد و دستورهای `UPDATE` و `SELECT` روی همان یادداشت کار می‌کنند. هر بار اجرای فایل دو یادداشت تازه می‌سازد؛ این تمرین فقط از `practice.db` استفاده می‌کند.

### برنامهٔ تمرین پیشنهادی

برای یادگیری، این ترتیب را دنبال کنید:

۱. برنامه را اجرا کنید و فقط فایل‌ها و پوشه‌ها را بشناسید.

۲. در کد، یک عنوان را پیدا کنید و ببینید در کدام صفحه ساخته می‌شود.

۳. تمرین‌های ۱ تا ۳ را با خواندن تابع `submit` پاسخ دهید.

۴. تمرین‌های ۴ تا ۷ را با نگاه‌کردن به `database.py` حل کنید.

۵. تمرین ۸ را دنبال کنید تا ارتباط دکمه و تابع را پیدا کنید.

۶. تمرین ۹ را انجام دهید تا افزودن داده با `INSERT` و پارامترها را تمرین کنید.

۷. بعد از اینکه این مسیر را فهمیدید، مفهوم `UPDATE` و `DELETE` را با مثال یاد بگیرید؛ هنگام تمرین روی دادهٔ مهم کار نکنید.

۸. پس از هر تغییر کوچک، برنامه را دوباره اجرا کنید و اگر خطایی دیدید، متن کامل آن را نگه دارید.

هدف این نیست که همه‌چیز را یک‌روزه حفظ کنید. وقتی بفهمید «کلیک از کجا شروع می‌شود، تابع بعدی کدام است، و داده کجا ذخیره می‌شود»، کم‌کم می‌توانید مسیر کامل برنامه را دنبال کنید.

## ۱۷. نکتهٔ امنیتی برای استفادهٔ واقعی

این پروژه برای یادگیری و اجرای محلی مناسب است، اما روش‌های امنیتی آن را نباید آمادهٔ استفادهٔ واقعی در نظر گرفت. رمزها با SHA-256 و یک salt ثابت نمونه‌ای هش می‌شوند و پاسخ پرسش امنیتی به‌صورت متن ساده ذخیره می‌شود. این روش‌ها برای سامانهٔ واقعی و اطلاعات حساس کافی نیستند.

همچنین نام کاربری و رمز پیش‌فرض مدیریتی فقط برای نمونه است. در یک سامانهٔ واقعی باید رمز پیش‌فرض حذف یا امن تغییر داده شود و روش مناسب نگهداری رمز و بازیابی حساب پیاده‌سازی شود.

## ۱۸. فرهنگ واژهٔ کوتاه

| واژه | معنی |
|---|---|
| Python | زبان برنامه‌نویسی‌ای که دستورهای پروژه با آن نوشته شده‌اند |
| Tkinter | ابزار Python برای ساخت پنجره و کنترل‌های گرافیکی |
| SQLite | پایگاه داده‌ای که اطلاعات را در یک فایل نگه می‌دارد |
| SQL | زبان نوشتن دستور برای خواندن یا تغییر دادهٔ پایگاه داده |
| تابع | مجموعه‌ای از دستورها با یک نام که می‌توان آن را فراخوانی کرد |
| پارامتر | ورودی‌ای که هنگام تعریف تابع برای دریافت اطلاعات مشخص می‌کنیم |
| آرگومان | مقداری که هنگام فراخوانی تابع به آن می‌دهیم |
| کلاس | الگویی برای ساختن اشیا و نگهداری داده و رفتار مرتبط |
| شیء | نمونه‌ای که از یک کلاس ساخته شده است |
| ویجت | جزء رابط کاربری، مانند دکمه یا کادر متن |
| رویداد | اتفاقی مثل کلیک یا فشردن کلید |
| callback | تابعی که بعد از یک رویداد، مثلاً کلیک، اجرا می‌شود |
| cursor | ابزاری برای فرستادن دستور SQL به پایگاه داده |
| رکورد | یک ردیف اطلاعات در جدول |
| ستون | یک نوع داده در جدول، مانند نام کاربری |
| commit | ثبت نهایی تغییرهای پایگاه داده |
| `self` | اشاره به نمونهٔ فعلی یک کلاس |
| `return` | برگرداندن نتیجه از تابع |

اگر در جایی از راهنما یا کد به واژه‌ای برخوردید که هنوز آشنا نیست، به همین بخش برگردید و سپس همان خط را دوباره بخوانید.
